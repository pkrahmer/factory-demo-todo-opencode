# HTTP API

What the schema cannot say. The schema itself is `docs/openapi.json` (generated by `make openapi`; a test fails when it is stale) and, while the server runs, `/docs` (interactive) and `/openapi.json`.

The service is for one user: there is no authentication. Where the todos are kept depends on `TODO_DB` (see *Storage*).

## Running it

```bash
uv run uvicorn app.api.main:app --port 8765
```

`app.api.main` is the composition root and the only `app.api` module that imports `app.repository`. `build_app(environ)` builds the whole application from an environment mapping: the service around the repository that `build_repository(environ)` returns (see *Storage*), and the storage kind that `/health` reports. The module's `app` is `build_app(os.environ)`.

`create_app(service, *, storage="memory")` in `app.api.app` builds the same application around any service, which is how the tests run it. `storage` is only what `/health` reports (`"memory"` or `"sqlite"`); it does not choose anything.

## Storage

The environment variable `TODO_DB` chooses where the todos live, read once when `app.api.main` is imported (that is, when the server starts):

- `TODO_DB=<path>`: the todos live in the SQLite file at `<path>`. The file is created on first start; later starts open it and find the todos as they were, so they survive a restart. A relative path is relative to the directory the server is started from. The directory itself must exist: if it does not, the server fails to start with `unable to open database file`.
- `TODO_DB` unset or empty: the todos live in memory, nothing is written to disk, and they are gone when the process stops.

```bash
TODO_DB=todo.db uv run uvicorn app.api.main:app --port 8765
```

The table is `todos`, created when it is missing; an existing one and its rows are left alone. Columns: `id` (the UUID's hyphenated form), `title`, `done` (a boolean), `created_at` (ISO 8601 text in UTC with microseconds, always ending `+00:00`, so that its text order is its time order). There is no migration: an existing `todos` table is used as it is. Statements are built from SQLAlchemy Core constructs, so a title such as `Robert'); DROP TABLE todos;--` is stored and returned verbatim.

## Endpoints

All bodies are JSON. A todo is returned as:

```json
{"id": "f9d48f8d-c7ed-43f3-be9c-c84dad617b58", "title": "Buy milk", "done": false, "created_at": "2026-10-19T13:09:19.344428Z"}
```

`id` is a UUID in its hyphenated form; `created_at` is ISO 8601 in UTC.

| Method | Path | Body | Success | Errors |
| --- | --- | --- | --- | --- |
| POST | `/todos` | `{"title": "..."}` | 201, the new todo (open) | 422 |
| GET | `/todos` | | 200, a list of todos in creation order | 422 |
| GET | `/todos/{todo_id}` | | 200, the todo | 404, 422 |
| PATCH | `/todos/{todo_id}` | `{"title": "..."}` and/or `{"done": true\|false}` | 200, the changed todo | 404, 422 |
| DELETE | `/todos/{todo_id}` | | 204, empty body | 404, 422 |
| GET | `/stats` | | 200, `{"open": n, "done": n, "total": n}` | |
| GET | `/health` | | 200, `{"status": "ok", "version": "...", "storage": "..."}` (see *Health*) | |

- **List filter.** `GET /todos?done=true` returns only the completed todos, `?done=false` only the open ones; without `done` all of them. Any other value is a 422.
- **Ids.** A `todo_id` that is not a UUID is a 422, an unknown one a 404.

### Health

`GET /health` is what a monitor polls. It answers 200 with exactly three fields:

```json
{"status": "ok", "version": "0.1.0", "storage": "memory"}
```

- `status` is always `"ok"`: the endpoint answers when the process is up, and there is no other value.
- `version` is the installed package version, `importlib.metadata.version("app")` (`0.1.0` in `pyproject.toml` today).
- `storage` is `"sqlite"` when the app was started with `TODO_DB` set and not empty, otherwise `"memory"` (see *Storage*).

The handler never touches the service or the repository; it reads the storage kind that `create_app` stored on the app. So it answers 200 also when the database cannot be read, and a 200 says the server is running, not that the todos are reachable. It has no parameters and no error response of its own, and it is tagged `health` in the schema.

```bash
curl -s localhost:8765/health
```

### Stats

`GET /stats` counts the todos for a glance at the data. It answers 200 with exactly three fields:

```json
{"open": 2, "done": 1, "total": 3}
```

- `open` is the number of todos that are not completed, `done` the number that are, and `total` is `open + done`: every todo.
- With no todos all three are `0`.
- The counts are taken from one listing of the repository each time the endpoint is called; nothing is stored or cached, so a todo created, completed, reopened or deleted is counted by the next call.
- It has no parameters (there is no filter) and no error response of its own, and it is tagged `stats` in the schema.

```bash
curl -s localhost:8765/stats
```

### Title rules

The schemas put no length or blank rule on `title`; the domain's rule applies (see *Title* in `docs/project-guide.md`). The title is stripped of surrounding whitespace first. Then:

- a blank title is a 422 with `title must not be blank`;
- a title of more than 200 characters after stripping is a 422 with `title must be at most 200 characters`;
- 200 characters is accepted, also with spaces around it, and `"  Buy milk "` is stored as `Buy milk`.

A missing `title` on `POST` is a 422 with `body.title: Field required`.

### PATCH rules

- The body must set `title`, `done` or both. `{}`, `{"title": null}`, `{"done": null}` and both `null` are a 422: a field sent as `null` counts as not set.
- With both fields, the title is applied first (rename), then `done` (`true` completes, `false` reopens). An invalid title is refused before anything changes, so the todo keeps its old title and its old `done` flag.
- Completing a completed todo, or reopening an open one, is not an error.
- The id and `created_at` never change.

Both changes are two writes against the repository, not one transaction; that was harmless in memory, and with SQLite a failure between the two writes can leave the rename applied without the `done` change. It is worth revisiting.

## Errors

Every error has the same body, a JSON object with one key holding one sentence:

```json
{"detail": "todo 00000000-0000-0000-0000-000000000001 not found"}
```

`detail` is never a list. Errors are mapped to status codes in one place, `app.api.errors`:

| Cause | Status | `detail` |
| --- | --- | --- |
| `TodoNotFound` | 404 | the error's message, `todo <id> not found` |
| `InvalidTitle` | 422 | the error's message (see *Title rules*) |
| Request validation (missing field, wrong type, bad `done` value, bad id, empty `PATCH`, body that is not JSON) | 422 | `<location>: <message>` of the first error, the location joined with dots |

Examples of the last kind: `body.title: Field required`, `query.done: Input should be a valid boolean, unable to interpret input`, `path.todo_id: Input should be a valid UUID, invalid character: found `x` at 0`, `body: Value error, set title or done`. The location prefix (`body`, `query`, `path`) is stable; the message after it is Pydantic's and may change with its version.

## Examples

Create a todo:

```bash
curl -s -X POST localhost:8765/todos -H 'content-type: application/json' -d '{"title": "  Buy milk "}'
```

```json
{"id":"f9d48f8d-c7ed-43f3-be9c-c84dad617b58","title":"Buy milk","done":false,"created_at":"2026-10-19T13:09:19.344428Z"}
```

List the open todos (leave out `?done=false` for all of them):

```bash
curl -s 'localhost:8765/todos?done=false'
```

```json
[{"id":"f9d48f8d-c7ed-43f3-be9c-c84dad617b58","title":"Buy milk","done":false,"created_at":"2026-10-19T13:09:19.344428Z"}]
```

Complete it, then delete it (use the `id` from the first call):

```bash
curl -s -X PATCH localhost:8765/todos/f9d48f8d-c7ed-43f3-be9c-c84dad617b58 -H 'content-type: application/json' -d '{"done": true}'
curl -s -o /dev/null -w '%{http_code}\n' -X DELETE localhost:8765/todos/f9d48f8d-c7ed-43f3-be9c-c84dad617b58
```

The second prints `204`.
